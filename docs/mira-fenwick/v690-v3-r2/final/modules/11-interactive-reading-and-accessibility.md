# Interactive reading, the deck and accessibility boundaries

The main interactive artifact is x2/albion.html. It is a self-contained HTML page with two inline scripts, no external script dependency and no image elements. A geometric canvas shows a central store, resident cottages, paths, fields, trees and a river. The scene is an intentional code-drawn visual under the user's image prohibition. It is neither an Unreal implementation nor a copy of commercial game artwork.

The controls alter the actual local model. A seed fixes the demand and production sequence. Resident count ranges from four to thirty. Supply has a declared base and a small seeded variation. One policy allocates a unit to every eligible resident before repeating; another serves residents in order. A checkbox withdraws Elm's future participation while preserving earlier records. Start, pause, step, reset and the 240-tick stop bound execution. Replay uses the original configuration plus the ordered consent changes and refuses a changed trace.

The comparison button evaluates two policies under the selected seed and reports a model-specific service distribution. The JSON inspector shows the complete synthetic configuration, consent events, resources and trace in a read-only dialog. It does not upload the record or silently create a download. The page never calls a model provider, operates a real credential, allocates a real asset or makes a public policy decision.

The browser checks used the in-app browser's accessible text and DOM interface. Stepping, withdrawal, replay, comparison, JSON inspection, keyboard Enter, Escape dismissal, start/pause, reset, seed editing, maximum population and the alternate policy were exercised. No console warning or error was observed in the scoped review. Desktop content width matched document width at the requested 1440-pixel viewport. At the requested 390-pixel viewport, a first 435-pixel document overflowed a 375-pixel content width. Setting grid children to min-width zero brought document width back to 375, with the canvas and controls fitting inside it.

The review checked the text design specification, essential copy, palette, heading and control typography, responsive geometry, dependency use and motion policy. It did not create screenshots or claim a pixel-for-pixel image comparison. Structural and keyboard checks are useful, but comprehensive screen-reader, voice-control, magnification, cognitive, language and affected-user evaluation remain separate work.

The four-tier deck contains 219 cards: one owner anchor, three pillars, seven placements of four practices, two hundred core proposals and eight supplementary task cards. Every child has exactly one parent in the immediately preceding tier. Card identifiers derive from a canonical preimage before adding the card_id field; the manifest separately binds the final file bytes. The stable-prefix and volatile indexes are explicit reading aids. They do not prove cache performance, memory retention, personhood or identity continuity.

Use x2/deck/index.html to browse, x2/deck/deck-index.json for machine selection, and x2/meta-tool-catalogue.json for capability lookup. Keep long context in these files and send only a compact pointer to the next task. An accessible layout is part of useful collaboration, but it never substitutes for the evidence or authority missing from the underlying work.
