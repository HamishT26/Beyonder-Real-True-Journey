# Retained failures and Method Flow

Thirty-four new Method Flow methods contain 162 aggregate witnesses: 108 passing and 54 failed. The failed count includes aggregate operation witnesses, while the negative ledger retains 1,200 individual malformed domain subjects plus fourteen operational or presentation failures, for 1,214 own negatives. Granularity is stated explicitly so individual subject records are not confused with aggregate witnesses. The selected predecessor baseline is then folded once, yielding effective counters without re-adding older owner totals.

Retained operational failures include startup read and wrapper errors, the oversized pretty task portfolios that exceeded the 100,000-word cap before official validation, the x1 exclusive-latch EEXIST, the local HTML parser failure, three global-installer dispatch or envelope failures, a PowerShell empty-pipe parser rejection before shared-reference copying, and the first final closeout-ledger validation rejection because its method-level retained-negative list was empty. Each recovery is additive. The exact failed ledger and validator receipt remain retained at zero success credit. The closeout ledger was corrected before commit, and no domain or already successful component was replayed.

The most reusable lessons are: materialize PowerShell collections before pipelines; treat asynchronous or timeout states as unresolved until exact state is read; separate input closure from runner envelopes; pair static HTML checks with one bounded browser observation; require non-empty method-level retained-negative lists even when all current closeout witnesses pass; and resume partial installation only from exact byte equality. These are same-owner workflow lessons, not independent reproduction.
