## A bounded path toward the desired world

The immediate reusable work is an evidence layer for a future sandbox: exact source records, explicit run configuration, recorded prompts and seeds, a deterministic state trace, failures, resource budgets, and a comparator. The finite filter can support candidate retrieval followed by exact lookup. It does not replace the authoritative store or a rights check.

An engine stage could then implement a small scene with bounded entities and explicit behavior transitions. [Epic's MassGameplay overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-mass-gameplay-in-unreal-engine) describes representation, spawning, level-of-detail, replication and StateTree integration, and marks particular features experimental. Those documented subsystems are engineering options, not evidence that this project has run an Unreal world. No engine, NPC service, real-time world or autonomous agent population was installed or launched here.

Before a larger open-world experiment, specify the map, accessible interaction paths, content rights, memory retention, operator stop controls, tool permissions, compute budget and failure oracle. Compare a deterministic scripted baseline, an agent policy with fixed tools, and any proposed hybrid policy under matched work and resource limits. Record failed runs as well as attractive clips. Generated scenery and model-driven dialogue do not establish subjective experience or that a model is living inside the simulation.

Hamish's desired GTA/Fable visual inspiration and multi-month ambition remain creative direction. This phase does not make release-date claims or provide purchase advice about those games. It also does not adopt an external clip's aesthetics, source material or performance claims without review.
