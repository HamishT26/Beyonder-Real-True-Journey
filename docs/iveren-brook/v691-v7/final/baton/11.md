# 11. Privacy, security, accessibility and resource limits

All workload labels are synthetic. No real participants, patients, beneficiaries, protected disclosures, credentials, private task identifiers, raw task streams or screenshots are used in the evidence artifacts. Primary-source retrieval was bounded; the fairness paper and legacy DRR full text were not inspected, and that limitation is retained. Their bibliographic records supply attribution and vocabulary, not external proof of the local contracts.

The two pure engine modules use closed field sets, finite integer checks, bounded lists and deterministic loops. They perform no network requests, filesystem writes, system-time reads or random draws. The CLI wrappers accept a single JSON request and return a JSON envelope. The shared wrapper constrains each group to four named operations. This is a bounded code review, not exhaustive security or production approval.

The local HTML report supplies labelled controls, headings, text equivalents, complete result data and a timeline table. Browser interaction and structural checks are recorded separately. Manual screen-reader, assistive-technology, low-vision, affected-user and cultural evaluations remain open. The report does not claim complete accessibility.

The owner branch and materialized owner directory each remain below two thousand files. Documents remain below one hundred thousand words. The modular baton is between ten thousand and one hundred thousand words. Authored file types are JSON, Markdown, text and HTML. No new package, PDF, image or screenshot artifact is introduced. The incremental spending target and observed spending are both zero dollars.
