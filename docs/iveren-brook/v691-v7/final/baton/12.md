# 12. Exact final seal, one canonical invocation and no replay

The final manifest binds the newly added closeout files. The owner manifest binds all owner files with only its declared circular self-exclusion and final-manifest relationship. The content seal binds the final narrative and evidence indexes. The four-tier deck has one owner anchor, three pillar cards, four practice cards and two hundred task cards. Its manifest binds exact bytes, and its parent links must have no missing target, tier skip or cycle.

The final canonical gate is a clean exact pushed owner head with matching local, upstream, tracking and fresh live remote references, zero divergence and the parentless four-commit topology. The canonical validator is invoked once only after that gate. Its external start latch prevents replay, and its output binds the exact current head, final file hashes and retained execution evidence. It does not run an unchanged source or predecessor suite. The validator must preserve any failed invocation rather than reusing its name or claiming it passed.

The canonical payload digest is SHA-256 over recursively sorted compact UTF-8 JSON excluding the payload_sha256 field, without a trailing newline. The file digest covers the full emitted JSON bytes. A correct digest demonstrates byte agreement, not empirical truth, identity continuity, authority or readiness. NOT_READY_FOR_STAGE_20 remains the terminal verdict.
