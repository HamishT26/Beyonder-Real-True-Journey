# Module 12 Flashcards shared discovery and the next investigation

The four-tier deck organizes this phase into one owner anchor, three pillars, four practices and concrete task/evidence cards. The deck contains 268 cards. Two hundred proposal cards link to their safe and candidate procedure records, one card represents the compound integration, thirty batch cards cover the three portfolio categories in both sessions, and twenty-nine method cards bind the recovery and refusal evidence. Child cards always have exactly one parent at the immediately preceding tier.

Each card has a content-derived identifier and a separate complete-file digest in the card manifest. The identifier is not a cryptographic identity for a person and does not supply a signature, credential or proof of authorship. A matching hash establishes a byte relationship. Stable and volatile indexes help select context, while the parent graph prevents an isolated task from silently becoming the source of authority for its owner. The folder organization does not prove prompt-cache retention or subjective memory benefits.

The current shared family guide points to schema v4. Twenty-six entrypoints were updated, and their old bytes were archived. Both current tooling pointers now select the complete thirty-three-capability catalogue. The x1 pointer state is retained separately from the later x2 state, so the final canonical can verify each historical state without pretending the mutable pointer stayed unchanged. Terminal publication after canonical success must follow the same pattern: preserve old bytes and publish a new current-state overlay.

For ordinary successor work, apply the future defaults: three relevant new direct packages, ten completed source bundles, four own practices and one successor recommendation. Keep both-session safe, candidate and refinement tranches within their requested bounds. Reuse the existing owner main branch below the file ceiling, and create a new worktree only when useful and authorized. A fresh blank branch needs a source-provenance link and must not claim Git ancestry it does not possess.

The recommendation for your next learning practice is experimental design for matched resource comparisons. It connects naturally with the new model cadence: define matching work, quality outcomes, settings, caches, input and output accounting, timing and the stopping rule before interpreting a difference. A comparison can be useful even when it shows no improvement. A lower resource total with a worse or incomparable result is not automatically an advancement.
