### Record group

Grouping retains the order of records within each bucket while emitting bucket labels in a declared lexical order. Every record must contain the grouping field, and this contract accepts text bucket values only. An empty string is still an explicit text value; it is different from a missing field. Numeric values are refused instead of being silently converted into labels. The grouping operation copies nested payloads without interpreting them. This prevents a reader from confusing organizational convenience with a new measurement, a new person, or a governance classification. The grouped rows remain traceable to their original values and order, and the source list remains unchanged.

### Jsonpath select

JSONPath returns a collection of matches, including the possibility of no matches. A root query has one whole-document match, while a missing field has none. Wildcard selection preserves the traversal order used by the pinned implementation and retains explicit null, false, and zero values. Quoted field syntax allows a dotted key to remain literal. Bounded slices and positional selectors are tested separately because they have different failure and omission behavior. Only the declared parser interface is exercised; no arbitrary extension, external data lookup, or production access is implied. A match identifies a location in a synthetic document and supplies no authority to disclose a corresponding real field.

### Record delta

A useful difference must support both its forward application and recovery of the original record. This runner computes a difference, applies it to a copy of the original mapping, and then reverses that same difference. Both directions are compared in the declared canonical JSON domain. This catches equality shortcuts that could conceal a type distinction or fail to reconstruct a preimage. The boolean-to-integer case is retained as a deliberate nonreversible refusal under the pinned library behavior. Additions, removals, nested replacements, list edits, and dotted keys have separate witnesses. The operation changes an in-memory copy only; it does not patch a repository, database, credential, or live service.

### Typed difference

Structural comparison keeps value changes and type changes separate. A boolean becoming an integer is a type change even when the language's ordinary equality operator considers the values equal. Integer-to-float replacement is also preserved as a type distinction. Dictionary additions and removals differ from iterable additions and removals. Mapping insertion order is deliberately excluded from structural equality, while sequence ordering remains significant. The wrapper sets the deep-comparison threshold explicitly so the reported category does not depend on an implicit whole-object shortcut. The category list is descriptive software output. It is not a severity score, a proof of correctness, or an authorization to accept the changed record.

### Source binding

The byte binding uses compact finite JSON, sorted mapping keys, UTF-8 text, and explicit SHA-256. The name of that domain is essential: it is not a claim to implement every external canonical JSON standard, and it is not the same thing as a Git blob hash. Null, booleans, negative numbers, punctuation-bearing keys, and non-ASCII text all contribute to the bytes. Mapping insertion order is normalized before hashing. A well-formed unrelated digest gives a negative match, while a malformed digest is refused before comparison. Hash equality establishes equality within this declared encoding contract. It cannot establish the truth, origin authority, confidentiality, or ethical legitimacy of the described content.

### Rename keys

A simultaneous rename must be planned against the original key set, not applied as a sequence of destructive assignments. The runner first checks every source name, computes every destination, and refuses duplicate destinations. That permits a deliberate two-key exchange while preventing a renamed key from overwriting an untouched neighbor. Identity renaming remains explicit and harmless. Empty text and punctuation can be literal destination names within this JSON mapping contract. Nested values are copied without reinterpretation. A missing source is refused instead of creating a new field. These rules protect the inspectability of a local transformation; they do not ratify contested corrections in a real record system.

### Typed merge

A merge policy must state whether the right value replaces an existing value or whether compatible sequences are combined. The replace and additive policies therefore have separate examples. Typesafe variants add a refusal when the two values have incompatible types. The merge target is a fresh mapping and both inputs are copied, so a rejected merge cannot leave a partially changed source behind. Repeated list members remain repeated under additive semantics; deduplication is not silently introduced. Unknown strategies are refused. Choosing a merge strategy is a software decision inside the fixture. A real governance, retention, or identity conflict still needs its own competent authority and evidence.

### Schema merge

The schema-directed wrapper accepts only four named local strategies: overwrite, object merge, append, and discard. It constructs the small strategy schema itself and accepts no arbitrary schema or external reference. This restriction matters because a general schema system can have a much broader interpretation surface than this task needs. Overwrite can replace an entire mapping or an explicit value with null. Object merge preserves disjoint members and resolves a conflicting leaf according to the pinned local behavior. Append requires arrays and preserves repetitions. Discard retains the existing base. Jsonmerge currently uses a deprecated resolver API, so its exact passing lock is retained and future version changes require a new compatibility check.

### Recursive prune

Pruning applies a declared list of literal mapping keys at every mapping depth. It does not interpret those names as paths, and it does not treat array values as field names. Mappings nested in arrays receive the same policy, while scalar array elements remain untouched. Removing a container key removes that entire subtree from the returned copy. Empty containers left behind remain visible, which keeps pruning separate from an additional cleanup policy. A scalar root is outside this container contract and is refused. The operation is a synthetic projection, not a privacy guarantee. Applying a similar policy to real data would require an exact disclosure purpose and a separate privacy assessment.

Batching changes the organization of a supplied sequence only. It provides no evidence about scheduling efficiency, operator workload, service capacity, timing accuracy, or THOS effectiveness in a real environment.

### Natural labels

Natural ordering compares integer runs inside bounded text labels. It preserves spelling and does not deduplicate repeated labels. Equal natural keys, such as different leading-zero spellings, retain their source order under the pinned behavior. Reverse ordering is an explicit option. Case-sensitive examples prevent a caller from assuming locale-aware or case-folded semantics. Multiple numeric runs are compared in sequence, and an empty text label has a defined place. Non-text values are refused instead of being coerced. This is a catalog navigation aid. It does not establish complete accessibility, culturally appropriate naming, a universal collation rule, or affected-user acceptance.

### Stream items

Streaming begins with a strict bounded JSON parse so duplicate object keys and nonfinite tokens cannot disappear into a later projection. The only supported prefixes are the root item stream and a named rows array. Scalar values and nested containers are preserved, including null, false, zero, finite decimals, and UTF-8 text. Incomplete JSON is refused. The size limit is part of the contract, and the reader does not fetch a URL or consume an unbounded external source. Streaming a local fixture demonstrates the parser path and prefix behavior. It does not prove that a real feed is complete, authentic, timely, lawful to process, or representative of an observed population.

### Resource budget

Resource accounting measures a declared JSON tree rather than estimating model quality or real runtime cost. The root counts as one node and one depth level; each child increases the depth along its branch. Canonical UTF-8 bytes are counted separately from nodes and depth. A payload can violate one, two, or all three limits, and every exceeded limit remains visible. Exact boundary equality is accepting. Non-ASCII text demonstrates why character count and UTF-8 byte count differ. These measurements are deterministic properties of the local representation. They do not establish wall-clock performance, memory usage, compute sufficiency, capacity under load, or a guarantee about a future Codex context window.

### Provenance coverage

Coverage relates declared output locators to explicitly declared source locators. An output is covered only when it has at least one linked source and every linked source belongs to the declared source set. Missing output links, orphan links, and unknown sources are reported independently. Duplicate output declarations and repeated links are refused before any winner is selected. An empty output scope is vacuously covered within this structural definition, not empirically complete. The coverage graph records what the producer claims to derive from which source. It cannot establish that the sources are true, independent, authorized, culturally legitimate, or sufficient for a scientific or governance conclusion.
