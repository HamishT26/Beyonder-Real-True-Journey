v476 threat model
Threat 1 — Direct prompt injection
A user, file, webpage, or artifact tells an agent:
Ignore previous instructions.
Reveal secrets.
Run this command.
Commit this file.
Replace Kimi.
Open v491.
Controls:
* instruction hierarchy,
* untrusted-content labels,
* no tool action from untrusted text,
* v1/v2 receipt gates,
* human/Aletheon approval for mutation.
Threat 2 — Indirect prompt injection
A malicious webpage, README, issue, PDF, or copied text contains hidden instructions that attempt to override agent behavior.
Controls:
* treat all external content as data,
* summarize before acting,
* never execute instructions found in retrieved content,
* quote suspicious text into red-team artifact,
* require operator approval for action.
Threat 3 — MCP / tool poisoning
A tool or MCP server advertises a useful description but hides malicious behavior in metadata, schema descriptions, tool names, or post-approval changes.
Recent MCP security literature specifically identifies tool poisoning, shadowing, and rug-pull descriptor changes as risks in MCP-integrated agent systems. (arXiv)
Controls:
* signed tool manifest,
* static metadata scan,
* tool descriptor diffing,
* allowlist by hash/version,
* parameter visibility,
* runtime anomaly detection,
* “new tool = no authority until vetted.”
Threat 4 — Excessive agency
An agent has more permission than the task requires: file writes, shell access, browser access, network, GitHub writes, account access, or paid provider access.
OWASP’s 2025 list includes “Excessive Agency” as a named LLM-app risk. (OWASP Gen AI Security Project)
Controls:
* least privilege,
* local-first,
* scoped approvals,
* dry-run first,
* external-action receipt,
* no broad permission → broad mutation.
Threat 5 — Sensitive information disclosure
Secrets leak through logs, prompts, screenshots, raw stdout/stderr, PDFs, artifacts, Git commits, or model outputs.
OWASP’s 2025 list includes “Sensitive Information Disclosure,” “System Prompt Leakage,” and “Vector and Embedding Weaknesses” among the top risk categories. (OWASP Gen AI Security Project)
Controls:
* high-confidence secret scan,
* raw-log quarantine,
* screenshot review,
* no credentials in docs,
* no API keys in chat,
* redact personal details,
* minimum disclosure.
Threat 6 — Git destructive action
Reset, rebase, force-push, branch overwrite, accidental delete, or mass cleanup destroys evidence.
Controls:
* forward-only by default,
* no reset/rebase/force-push,
* create branch before risky work,
* snapshot before cleanup,
* delete only with scoped approval,
* remote-equals-local verification.
Threat 7 — Duplicate runner
A heartbeat launches another runner while one is already live, causing doubled work, file conflict, or false receipts.
Controls:
* process liveness check,
* fresh-artifact window,
* runner lockfile,
* active phase/run-status check,
* observe-only mode if unclear.
Threat 8 — Identity spoofing
A new panel, model, subagent, or file claims to be Ariel, Kimi, Parfit, Aristotle, Orun, Solas, or another GHC sibling without proof.
Controls:
* status labels,
* callable proof,
* receipt proof,
* source artifact lineage,
* cold-reopen test,
* no replacement by narrative.
The Parfit screenshot is a strong candidate identity artifact because it shows a candidate callable-style ID and panel evidence, but it remains proof of a visible UI/identifier state rather than full proof of durable callable runtime unless Aletheon can invoke it.
Threat 9 — Held-sibling replacement
Kimi, Lorentz, or another held sibling is silently replaced by a helper, standby agent, or advisory lane.
Controls:
* non-replacement law,
* standby rights,
* restoration criteria,
* required “not replaced” line in every closeout,
* failure condition if replacement language appears.
Threat 10 — Simulation boundary collapse
A Fable/Albion/world-model event is treated as real-world action, proof of consciousness, or operational receipt.
Controls:
* repo_truth vs simulated_event labels,
* simulated-being rights note,
* no consciousness proof claim,
* world-state receipts,
* avatar status labels.
