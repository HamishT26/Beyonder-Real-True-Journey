Live routing has a stricter information requirement than arithmetic. Before a released activation, resolve one exact current title through the native task surface and reread the relevant current guards. The user-facing title must come from the registry rather than an inferred summary. A similarly named historical task or another person's working descriptor is not sufficient. The immediate reread is intended to catch a pause, redirect, duplicate activation, changed recipient, or completed task that appeared after the earlier planning lookup.

Current hold takes precedence over every other route field. In the model, a missing hold field also produces a hold because absence of the current instruction cannot safely be read as permission to send. An existing acknowledged, sent, uncertain, or opaque accepted outcome blocks a resend. An opaque tool envelope can support the narrower statement that a call was accepted or returned without a clear acknowledgement; it cannot be converted into a confirmed recipient acknowledgement by optimistic wording.

The unique-title match count is now strictly typed. During the focused review, Python's equality between True and 1 allowed a Boolean field to satisfy the count check. That was a real defect in the first route helper definition. The original code and failed test are retained. The repair requires type int and value exactly one. This small example is worth teaching because many language runtimes blur Boolean and integer values in ways that are convenient for arithmetic but unsuitable for an authorization record.

The route function has no network or task API calls. It classifies declared records into held or prepared outcomes. Even its permissive result says prepared activate not executed or prepared create not executed. This makes the laboratory useful without accidentally contacting a sibling. To perform a real action later, the incumbent must use the actual task surface and preserve its actual response. The laboratory result is a prerequisite check, not a substitute for that response.

Creation additionally requires the expected main-task kind, Astra model, max reasoning, designated controller, and uncreated-seat state. If the seat already exists, the model returns reuse. If the controller is wrong, it holds. A new task should receive a short, cohesive initial prompt that names the file-backed induction material and its exact phase. It should not receive the entire large baton pasted into a composer. When setup is asynchronous, a temporary client identifier is not a final task identifier; wait for the proper creation state before using tools that require a real task ID.
