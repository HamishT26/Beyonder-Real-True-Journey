# Toolchain and safe use

The special remaster adds thirteen direct packages: ten Python libraries and three Node libraries. They were researched against current package metadata, resolved into an isolated D-drive environment, checked against artifact hashes and dependency constraints, audited, installed, and exercised. The shared global Python installation and the desktop application were not upgraded as part of this work. The package count refers to direct additions. Transitive dependencies and the pip bootstrap are recorded separately and receive no new direct-tool credit.

The Python selections are SymPy 1.14.0, mpmath 1.3.0, SciPy 1.18.1, statsmodels 0.15.0, RDFLib 7.6.0, PyLD 3.3.0, pySHACL 0.40.1, PROV 3.1.0, rfc8785 0.1.4, and msgspec 0.21.1. The Node selections are mathjs 15.2.0, decimal.js 10.6.0, and n3 2.7.4. These versions describe the current installed transaction. A future phase should research its own additions and preserve its own lock rather than assuming that latest metadata is unchanged.

The mpmath choice is an important compatibility lesson. The latest candidate discovered during research was 1.4.1, but SymPy's declared dependency interval required mpmath below 1.4 and at least 1.1.0. Installing the latest version of every package independently would therefore have produced an inconsistent plan. The selected 1.3.0 pin satisfies the declared interval. The rejected latest candidate remains in the planning research, and the compatibility correction is recorded with zero success credit for the incompatible condition.

Python installation used wheels only. The resolved wheel set contains thirty packages, each with a name, version, filename, byte count, source URL, and SHA-256 digest checked against the package registry. The exact lock records hashes for installation with hash checking enabled and a local wheelhouse. The dependency audit was performed against the resolved versions, including the pip infrastructure version, before the main locked environment installation. A successful audit means the checked advisory source reported no known vulnerabilities for that snapshot; it is not a guarantee that every future vulnerability is known.

The Node project uses exact direct pins and a package lock. Lifecycle scripts were disabled while producing the lock and during the clean installation. The advisory audit passed before the final installation step. The lock records transitive versions and integrity values. This approach keeps a future reproduction concrete: it names the dependency graph actually installed rather than leaving a broad range to resolve differently later. A future owner should retain the lock and its audit date with the corresponding phase evidence.

SymPy is used with trusted symbolic objects, not arbitrary strings from mail or a source document. Its smoke checks the variable-coupling product rule and rejects the omitted derivative term. mpmath exercises high-precision cancellation against a binary64 counterexample. SciPy performs quadrature on a known integral and refuses a root bracket without a sign change. statsmodels recovers the coefficients of a trusted linear example and rejects mismatched sample dimensions. These are small functional demonstrations, not claims of numerical correctness for every possible use.

RDFLib parses inline Turtle data and rejects malformed syntax. PyLD expands a controlled inline context and refuses an unknown context through an offline loader. pySHACL checks a declared integer property against valid and invalid graphs while imports, JavaScript, and advanced features remain disabled. PROV serializes and reads back a small provenance document and rejects an unregistered namespace. These libraries can retrieve or interpret richer external material in other settings, so the bounded invocation profile is part of the evidence, not an incidental detail.

rfc8785 supplies canonical JSON behavior for its declared number domain and rejects a nonfinite value. msgspec supplies typed decoding and rejects a string where the fixture requires an integer. The Node smokes use mathjs's direct arithmetic and unit APIs, decimal.js's explicit decimal values and finite-number check, and n3's inline RDF parser. The phase does not expose an arbitrary expression parser to untrusted input. A future owner should preserve that distinction if adding a user-facing interface.

The private local toolchain map in the family toolbox gives the actual D-drive interpreter, wheelhouse, Node project, and module directory. Use Python with UTF-8 enabled. For the scoped Node fixture, set its module path to the isolated project rather than moving packages into the system profile. The existing npm global prefix remains on D. Download caches, temporary files, retained installation logs, and package environments also remain on D. Small curated skill metadata and portable helpers occupy the essential Codex skill directory.

The historical toolbox references contain eighty-eight unique package names across several previous installations. Adding the current thirteen gives a union of 101 names. That union is a catalogue, not a freshly executed test suite or proof that every historical tool is globally available in the same interpreter. Some packages live in isolated environments. Some names appear in multiple historical lists. Select tools because their function helps the current task, and record which interpreter or project supplied the actual invocation.

The observed Codex CLI version was 0.153.4 and matched the official latest npm version during this review. No CLI update was needed. The current service tier was default. Official speed documentation distinguishes Codex credit consumption from API token pricing: Astra Fast uses 2.5 times Standard credits in Codex, while the cited API Fast token pricing uses a different two-times measure. A speed multiplier is also different from elapsed task time. Do not infer that a slower or faster model setting must change the wall-clock duration of every phase.

Future ordinary bundles have a three-package target, while this remaster had the special thirteen-package request. Choose complementary tools with real use cases, exact provenance, compatibility review, and positive and adverse smokes. If an install fails, inspect the partially written environment and retained logs before retrying. Resume only the failed step when appropriate. Do not rerun a completed transaction for confidence, and do not count a package as exercised merely because its installer printed success.
