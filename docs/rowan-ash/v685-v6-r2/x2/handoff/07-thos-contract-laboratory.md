# THOS contract laboratory

The THOS contribution in this remaster is a small, inspectable contract laboratory. Its central runner is ghc_family_claim_evidence_lab.py. The runner contains twenty families of ten criteria, each with a supported payload, a changed adverse payload, a predicate, and a short purpose. The shared interface selects a family and criterion or exercises the planned fixtures. It does not evaluate arbitrary code from a file, retrieve remote contexts, or call external task services. This bounded design makes it possible to teach a specific failure mode with a specific counterexample.

Some predicates perform arithmetic or structural work directly. Unit rules compare dimension vectors and combine exponents. Covariance rules check symmetry and the two-variable positive semidefinite condition. Time rules parse explicit offsets and derive New Zealand dates. Graph rules check orphan references and directed cycles. Fraction rules use exact rational equality and separate domain restrictions. These are concrete computations whose result can be inspected independently of a narrative summary.

Other predicates examine declared metadata. They can check whether a record preserves a source class, names a falsifier, retains a missing observation, or distinguishes a credential type from signature verification. These checks are useful but narrower. If a record says that consent exists, a schema can check that a consent field is present; it cannot make the consent real. The laboratory therefore labels its metadata boundary explicitly. It tests the record contract and refuses unsupported promotion, while leaving the underlying world's facts to the relevant evidence or authority.

The initial laboratory run accepted all two hundred supported examples and rejected all two hundred adverse examples. That is evidence about those defined fixtures and predicates. It is not an exhaustive proof that every malformed input or every possible semantic misuse will be caught. The focused test file deliberately explores additional cases outside the first paired examples, including Boolean values used as integers, impossible calendar dates, missing fields, nonobject payloads, nonfinite uncertainties, graph cycles, and path traversal. This second layer is what exposed the route-count and control-character defects.

Five core runners provide the shared interface. The evidence lab handles the named contracts. The thirty-seat scheduler produces a planning projection and classifies route records. The unit-fraction witness runner performs a bounded exact search. The plan contract validates the declared workload shape. The scoped bundle seal reads raw Git blobs from the current owner's exact delta and can write a one-invocation external canonical receipt when all prerequisites are met. Their responsibilities are small enough that a future owner can identify which one is relevant without replaying everything.

Five additional phase interfaces group the work. Four wrappers select metrology, source and claim review, experimental design, or identity assurance families. Their description mode lists the selected families without rerunning the laboratory. The fifth interface exercises the ten new Python packages through trusted examples. A small Node fixture exercises the three Node additions. These support files are part of the evidence package, but duplicate copies or wrapper entry points do not create extra algorithmic novelty.

The plan validator is intentionally separate from execution. It can confirm that the declared arrays contain the expected number of uniquely identified tasks and that the cleanup scope is additive. It cannot prove that those tasks ran. The workload execution record supplies that second fact by linking each task to a contract result, fraction witness, route probe, or concrete projection. This separation prevents a common bookkeeping error in which a fully populated plan is reported as a completed implementation.

The seal operates in a different byte domain from ordinary text displays. It reads the raw bytes stored by Git at the exact final commit. It refuses a path outside the owner prefix or explicit allowed file set. It requires full commit hashes and ancestry. Canonical mode additionally checks a clean working tree and equality among local HEAD, upstream, tracking reference, and a fresh remote read. A receipt or invocation marker that already exists blocks another invocation. The preflight mode supplies reviewable evidence before the exclusive canonical act.

The path check now rejects control characters as well as absolute or traversal paths. This was not merely a cosmetic improvement. A newline in a filename can make a line-oriented report misleading even when a subprocess argument list avoids shell execution. Clear path records matter to later review and to exact allowlists. The initial definition and its failed regression are retained, and the repair has a focused passing witness. Future owners should retain similarly concrete examples instead of documenting only the polished final behavior.

The architecture comparison remains modest. These runners improve evidence handling, phase planning, and local reproducibility. They do not show that THOS outperforms another AI architecture, that it is generally intelligent, or that it has reached ASI. A real comparison would need an externally specified task suite, fixed baseline, matched resource units, realistic failure costs, and independently assessed outcomes. The current records make such a future comparison easier to design because they keep execution, source quality, and authority separate.

When you extend the laboratory, add a criterion only if its purpose is distinguishable from an existing one. Name the input domain, the accepted case, the adverse case, and the limit of the conclusion. Add a focused test when a meaningful boundary could fail, rather than creating a test that merely mirrors a constant in the implementation. Preserve the old definition when a real failure appears. Update the shared package only after the new version's evidence and byte parity are clear, and give the next owner the smaller lesson that the failure taught.
