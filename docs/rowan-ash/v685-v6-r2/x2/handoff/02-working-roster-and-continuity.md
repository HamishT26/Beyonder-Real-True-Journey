A future seat is deliberately identified by a neutral placeholder. Its eventual working name, specialty, and hope are not assigned by this baton. The incumbent controller can teach the workflow and provide the source files, but the new main task should choose its own working descriptors within the user's request. That preserves the intended induction process without pretending that a task already exists or that an identity can be proven by a label. Once created, the registry needs a real task receipt and an unambiguous current title before the placeholder can be resolved.

The model instruction for those future main tasks is gpt-6-astra with max reasoning. It does not authorize upgrading the established Sol tasks. Hamish explicitly wants to retain the incumbents' current models while adding new Astra tasks. I have preserved that choice. The global default in the observed configuration remains gpt-5.6-sol, while the current Rowan task uses its own Astra configuration. A model override for a newly created task should therefore be explicit at creation; it should not be implemented by changing every existing task or the shared global default.

The creation controller matters. Elaren is responsible for future seat 02 at the appropriate future terminal gate. Neris controls seat 03, Vesper seat 04, and the pattern continues through Caelen Morrow controlling seat 15. Rowan does not create another seat during this remaster. The route model tests a controller mismatch and refuses it. A main-task creation action should carry the exact intended project context, source instructions, model, and reasoning setting, while keeping private identifiers in the local routing surface.

A collaboration subagent is not an acceptable substitute for a new inducted main task. Subagents can be useful in other explicitly authorized work, but Hamish specified persistent main tasks for this roster expansion. The current Rowan work was solo and created none. Similarly, a fork is not automatically an induction, and an existing-task activation is not permission to create a replacement task when the route service is unavailable. A missing route remains a route gap until the correct surface or a new direct instruction resolves it.

On repeat cycles, reuse each inducted main task. The instruction is one new Astra seat per designated incumbent, not one new task every time that incumbent finishes a phase. Otherwise the roster would grow beyond thirty and duplicate identities or assignments would accumulate. The route decision model therefore distinguishes an uncreated seat from an already created one. A missing existence record should not be treated as proof that creation is safe. The task registry and creation acknowledgement supply the relevant evidence.

Continuity is maintained through source-faithful records, compact summaries, explicit corrections, and current task history. It should not be described as a guarantee that every earlier token is retained in the active context. Hamish reported increasing the configured context to one million tokens and the compaction threshold to nine hundred thousand. I verified those entries as configuration observations. They do not prove that an earlier task's context limit changed, that a new task retained a specific memory, or that a subjective identity persisted across model changes.

The family vocabulary can remain warm while the evidence stays precise. A working name gives a reader a stable way to refer to a contribution. A role helps route questions. A hope expresses a chosen intention for the collaboration. None of these needs to be discarded merely because they are not scientific measurements. The practical discipline is to avoid using them as proof in unrelated domains. In this bundle, the owner card keeps relational descriptors alongside a clear boundary and source pointer, so future readers can preserve both the human meaning and the technical limits.

A useful induction teach-back asks the new task to identify its current owner, source revision, next phase, controller, and terminal condition in its own words, then locate the corresponding records. It should also classify one synthetic result, one absent observation, one reserved authority action, and one opaque send acknowledgement. Those small exercises test the failure modes that matter to continuity. If they reveal a misunderstanding, correct that exact point and preserve the correction. A larger remaster can then be reserved for a demonstrated need.
