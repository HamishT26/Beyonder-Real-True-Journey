# 10 — Installed tools, selection and practical use

The curated tool bank provides five public interfaces. The structure capability covers the explicit net inventory, incidence table and conservative independent-pair check. The firing capability covers enabled actions, single firings, ordered sequences and local commutation. The invariant capability checks supplied place and transition certificates, weighted marking comparisons and positive-certificate capacity bounds. The reachability capability covers complete finite graphs, deadlocks, exact shortest goals, L4 liveness and terminal components. The evidence capability represents interpretation limits, missing uncertainty models, empirical gaps and authority reservations.

Each public interface accepts UTF-8 JSON on standard input, with exactly three top-level fields: operation, net and parameters. The net must declare its synthetic status, case identifier, ordered places, initial marking and complete named pre/post transition vectors. The exact parameter shape depends on the chosen operation. Use a frozen proposal example as a contract reference, then replace the entire input with a separately documented model if that is the authorised next task. Do not rely on the fixture name to supply hidden data, and do not strip unknown fields silently.

The source runner files live under `x2/promotions/runners`, and the support modules live under `x2/promotions/code`. The installed D-first bank uses the corresponding `petri-net-v1/runners` and `petri-net-v1/code` layout. Keeping this layout intact preserves relative imports. The global skill documents give the matching interface names and limits. Essential discovery documents are installed in the global skill directory; the executable text modules remain on D. No third-party library was required for these finite computations.

The current Meta Tool Box catalogue contains forty cards: twenty local skill documents, ten local runner interfaces, five curated skills and five curated interfaces. These are explicit paths in the owner phase, with source hashes, caller references, execution scope, rollback and protected gates. The catalogue is not a scan of every package or every sibling branch. Shared trigger words can legitimately overlap between an operation skill and the curated group that contains it. Collision detection highlights such overlaps for review; it does not pick a winner or authorise overwriting another capability.

To choose a tool, start with the required operation and the data model. Verify that the exact caller interface supports that operation and that the parameter convention matches the current input. A search result is only a discovery aid. A capability title, model family name or familiar word in a description is insufficient to justify execution. The corrected query and collision adjudication files show this principle concretely for transition liveness. The result should be inspected as typed data, with its outcome and boundary fields retained.

If a new request is refused, retain the request and the exact error first. Classify whether the problem is unsupported shape, a missing parameter, an invalid net, resource overflow, an absent prerequisite or a genuine implementation defect. Change only the smallest relevant dependency. A larger supported model may require a different tool rather than a larger arbitrary limit. An empirical or authority gap requires new evidence or a properly scoped decision, not a permissive parser change. A rejected subject does not become successful just because a later corrected subject passes.

The next two study recommendations are concurrency semantics and refinement, and experimental design for model adequacy. The first could compare this Petri-net representation with a clearly specified labelled transition system while retaining the exact property being preserved. The second could formulate what observations would justify mapping a real process to markings, with uncertainty, baselines and falsifiers. Both recommendations are learning directions. Neither is a professional qualification, a request to create a new main task, or permission to deploy on another person's system.
