A weighted place/transition net in this implementation consists of ordered places, named transitions, nonnegative integer input and output arc weights, and an initial nonnegative integer marking. The marking records how many abstract tokens occupy each place. The words input and output describe the model's bookkeeping. They do not say that a token is a joule, a person, a mental state, a legal right or an actual machine resource. Such a mapping would require an additional measurement or operational model and its own evaluation.

For a marking m and transition t, enabling means that every place has at least the number of tokens demanded by the corresponding input arc. Firing is defined only when that condition holds. It subtracts the input vector and adds the output vector. The incidence column is the output vector minus the input vector. The matrix is useful for algebra, but it is insufficient by itself to reconstruct enabling conditions. A self-loop can demand and return the same token, leaving a zero incidence entry while still blocking a transition when that token is absent.

A supplied place-weight vector is checked by multiplying it against each incidence column. When every residual is zero, the weighted sum is preserved by each firing. If every weight is strictly positive, the initial weighted sum provides a finite upper bound for the number of tokens in each place. The bound need not be tight: the fork-and-join example has a derived upper bound of two for intermediate places even though their observed reachable maximum is one. This implementation verifies supplied certificates. It does not compute a complete basis of all invariants.

A supplied transition-count vector is checked in the other direction, against the incidence rows. Zero aggregate change means the multiset of transitions balances algebraically. It does not prove that the transitions can be arranged in a feasible sequence from the initial marking. The cycle example makes the distinction immediate: one start and one finish balance, but finish cannot occur first when only the idle place is marked. Keep a concrete ordered firing witness when feasibility is the question. Do not replace it with a count vector.

The independent-pair operation uses disjoint full arc support as a sufficient structural condition. It includes both consumed and produced places. This deliberately conservative condition does not claim to detect every possible form of independence. A structurally independent pair may also never be coenabled in any reachable marking. The commutation operation asks a more local question: at one supplied marking, are both transitions enabled, can both orders fire, and do the two orders end in the same marking? A missing second step is a failed commutation witness, not an implicit success.

Reachability uses explicit breadth-first exploration, with transitions considered in deterministic name order. It records every discovered marking and edge. The function returns a complete graph only after the queue is exhausted. If an intermediate marking exceeds sixty-four tokens in a place, if more than 512 states would be required, or if the edge budget would be exceeded, it refuses. A refusal is preferable to labelling a partial graph complete. These engineering limits are part of the interface; they are not a theorem that larger nets are invalid or unsafe.

The liveness predicate uses an explicit finite L4 convention. For each transition and every reachable marking, it asks whether there exists a future reachable marking at which that transition is enabled. This is a possibility statement. It does not say that a particular scheduler will eventually select the transition. In the mutex example, the A-only cycle can repeat while B is never selected, even though B remains possible from each reachable state. Fairness requires additional assumptions. No timing, fairness or probabilistic scheduler model is smuggled into the liveness result.

Strongly connected components are groups of reachable markings that can reach one another. A terminal component has no outgoing edge to another component. It can be a continuing cycle, a single deadlock, or another finite closed behaviour. A terminal component does not by itself show success, harm, benefit or consent. The permanent trap is a terminal singleton even while its token-conservation certificate remains valid. This gives a concrete reason to separate structural conservation from progress properties.

These distinctions support all three pillars without promoting one kind of evidence into another. THOS gains a bounded executable model of process interactions. GMUT gains exact examples of conservation, representation and counterexamples to invalid inference. Freed ID and CBR gain visible responsibility, source lineage, refusal states and authority reservations. None of those software results establishes a new law of nature, empirical support for a Theory of Everything, an ASI architecture, or the legal validity of a governance system. The constructive next step is to formulate narrower, falsifiable questions and preserve the evidence needed to answer them.

The case tables preserve operation, fixture, frozen definition digest, expected output, observed output, predicate result and substantive disposition together.

There are twenty-seven additional x1 tests and seventeen additional x2 tests. They exercise behaviour that the main happy paths alone would not establish: cancelling self-loop arcs, infeasible ordering of a balanced transition multiset, conservation-compatible but unreachable markings, coenabled conflicts, positive commutation, empty sequences, invalid certificates, malformed shapes, token overflow, state-budget overflow, terminal singletons and fairness limitations. The x1 invariant property test contains ninety individual arithmetic assertions. Those assertions are reported as an internal test denominator, not ninety external replications.

The x2 liveness comparison uses a separate fixed-point relation calculation over the hand-declared edge tables. It does not reuse the production engine's generated transition graph as its oracle. This reduces one form of shared implementation dependence and makes the result easier to inspect. Both implementations were still written and run by the same owner. Algorithmic separation is not independent reproduction by another person, organisation or implementation team. That limitation remains explicit in each record.

Open boundaries and next work

The five empirical gap records and five authority gate records are active limits, not decorative caveats. Each is linked to a concrete fixture so that a future proposal can state what it would actually mean to evaluate that model. For example, mapping a real buffer to the abstract empty and full places would require a definition of observations, a sampling procedure, a treatment of missed or delayed events and a prediction that could fail. None of that is supplied by the current integer vectors. The gap remains open until the necessary evidence is present.

The fifty exact packets cover ten missing prerequisites for each fixture: a specific deployment target, affected-party authority, professional review, independent security review, independent privacy review, governed observations, preregistered prediction, measurement uncertainty, external benchmark parity and accessible-user evaluation. General owner-work authorisation is recorded, but it does not magically provide these prerequisites. Every exact subject remains unexecuted. A future owner may refine a packet into a concrete proposal, retaining the missing element and the evidence that would resolve it.

The thirty blocked packets cover six unsupported actions for each fixture: treating tokens as consciousness, claiming that conservation proves liveness, deploying without affected authority, declaring empirical GMUT confirmation, erasing original failed evidence and replaying an accepted successor delivery. These remain blocked. Their inclusion is not a prediction that the action will be attempted, and it does not turn the list into an approval grant. They are explicit boundaries on inference and workflow behaviour.

Ten successor skill ideas and ten runner ideas are preserved in the plan. They include coverability review, fairness review, invariant-basis review, net-refinement review, partial-order review, a boundedness gap, a PNML profile, place-order migration, external comparison and adequacy evaluation. They are proposals only. No implementation, installation or validation credit is assigned to them. A successor should choose the few that suit its current phase and formulate new inputs and falsifiers rather than inheriting a promise to build everything indiscriminately.

A coverability interface would ask a different question from exact-marking reachability. A fairness interface would need an explicit class of schedules and a property whose truth depends on it. An invariant-basis tool would need a declared coefficient domain, completeness claim and comparison against an established method. A PNML interface would need a specific supported profile and careful handling of unsupported constructs. A place-order migration would need a reversible coordinate map. These are concrete avenues for improvement, each with a different proof obligation.

Manual accessibility remains open. The HTML report provides headings, navigation, table captions, scoped headers, visible focus styling and a reduced-motion preference. Those structural features are useful but do not establish complete accessibility. No screen-reader session, keyboard-only user study, low-vision assessment, Maori-language review or affected-user evaluation was performed in this phase. A future review should preserve the report's real content and task flow rather than treating a checklist alone as proof of usability.

Independent reproduction also remains open. The exact requests, expected outputs and code allow another appropriately authorised reviewer to inspect the work. Such a review has not occurred merely because the files exist or because this owner wrote an alternate oracle. Preserve this distinction when sharing the artifacts. A reproducibility package is a preparation for independent work; it is not a receipt for that work having happened.

The Stage 20 verdict remains NOT_READY_FOR_STAGE_20. This is compatible with useful progress. The phase supplies a small, testable component and clearer reasoning boundaries. It does not claim that all remaining research, engineering, social, ethical or governance questions have been solved. The most useful continuation is to select a bounded question, state what evidence could change the answer, and keep both positive and negative findings available to the next reader.
