# Module 10 - Method Flow, retained failures and count boundaries

At the x2 evidence boundary, Rowan's Method Flow ledger contains 53 methods, 998 witnesses, 237 failed witnesses, 761 passing witnesses, 106 state transitions and 53 recommendations. The source's successor-visible baseline is retained separately as 119 methods, 515 failed witnesses and 1,181 passing witnesses. Combining those declared layers arithmetically would give 172 methods, 752 failed witnesses and 1,942 passing witnesses, but the layers are not flattened into an assertion about the entire historical family archive. Their scopes and source hashes remain explicit.

The 200 new proposal records extend the declared proposal chain from 18,231 to 18,431. This is a bookkeeping lineage count. It is not a count of new scientific discoveries, independent inventions, experiments on real systems or validated laws. The twenty operation families implement known mathematical and evidence concepts through new owner-local examples. The 200 inherited selections retain zero new execution and novelty credit. Their lossless keyed projections are counted as source-record refinements, with an explicit statement that no host cleanup was performed by those rows.

The failed-witness denominator includes several different kinds of subject. Two hundred are deliberately inadmissible candidate requests whose refusal checks passed. Three are adverse package inputs. Ten are requests outside a paired runner's operation scope. Three are unrestricted mathematical claims contradicted by explicit finite examples. Twenty-one are operational or presentation failure groups. These subjects are retained because their failure or inadmissibility is part of the evidence. A passing guard witness is recorded separately and does not make the subject itself successful.

The first intake failures concerned presentation and source discovery. Raw baton output and a verbose indexed view exceeded output budgets. A combined roster presentation was too large. A filename query included a nonexistent reports directory. A native source turn returned an empty item list. A wildcard branch read and a recursive historical tree read stalled. A broad recursive folder read was stopped without a usable displayed result. Each initial attempt retains zero credit for the evidence it failed to provide. Later bounded reads supplied the actual source and EOF witnesses.

They did not change the source content or authorize a broad rewrite of family guidance. The selected source paths and byte bindings remain in the planning source window, with the full immediate baton handled separately.

That is transport evidence. It is neither a source canonical replay nor an empirical replication of a predecessor's work.

Two x1 metadata-writer errors occurred after the calculations had passed. The first was inconsistent indentation and stopped before any receipt write. The second counted zero tests because it assumed LF line endings in a retained CRLF unittest transcript. The failed writer bytes were preserved. The correction used splitlines while retaining the original transcript and reused already written metadata only when the bytes matched exactly. It then completed the remaining ledger. None of the passed calculations, unit tests or package smokes was rerun to repair that formatting dependency.

Every method keeps its failed references, scoped workaround, recurrence guard, rollback and bounded recommendation state. A validated state means that an attributable passing witness exists for that declared procedure. It does not mean the method is preferred for all work or that a broader professional, legal, cultural, privacy, accessibility or scientific claim has passed. Some administrative methods reference an existing field-refusal subject for context; the ledger explicitly denies an additional method-specific adverse observation for those references. Do not invent new failed subjects merely to fill a schema field.

The useful operational lesson is to identify what actually failed before deciding what to run again. A timed-out client can leave a completed commit. A truncated display can coexist with an intact file. A valid test run can be misread by a summary parser. A failed canonical can coexist with a valid separate component recovery. These distinctions should guide Neris's next phase: inspect the concrete state, preserve the first observation, repair the smallest justified dependency and avoid giving repeated observations new novelty or completion credit.
