# Module 08 - Packages, environment and resource use

The three new direct additions are SymEngine 0.14.1, opt_einsum 3.4.0 and NumExpr 2.14.2. NumPy 2.5.3 is the fourth distribution in the isolated closure. NumPy was already a family capability, so this pinned dependency copy does not count as a fourth new family tool. The package plan was prepared from current PyPI release metadata, with a single compatible Python 3.12 Windows wheel selected for each distribution. The exact URLs, byte sizes and SHA256 values are preserved in the planning files.

The wheels were downloaded to D, checked against their frozen size and digest, and installed through a hash-locked, wheel-only, offline installation step into D:/GHC-Archives/toolchains/rowan-ash/v689-v5/python. Temporary files and package cache data also used D. No source build, host interpreter replacement, global package upgrade, desktop update, credential change or Windows feature change was part of the transaction. The environment is isolated so a future owner can choose whether this particular tool set fits a new task.

SymEngine supplies a symbolic comparison, not an oracle about nature. Its accepting smoke expands a fixed polynomial identity to zero. Its adverse smoke supplies a deliberately malformed fixed expression and observes a RuntimeError. The later study differentiates weighted path energies symbolically and compares each derivative with twice the corresponding Laplacian component. Five small path sizes produced zero residuals. This confirms those symbolic calculations under the installed package and declared algebra; it does not independently establish a physical field equation.

opt_einsum supplies a separate array contraction path. Its accepting smoke multiplies two explicit two-by-two integer matrices and matches the known result. Its adverse smoke presents incompatible contraction dimensions and observes a ValueError. In the later comparison, ten frozen energy cases are assembled with an incidence matrix and contracted through the package. The calculation is separate from the main exact evaluator's scalar loops. The inputs are small enough that the chosen integer quantities remain within the stated numeric limits.

NumExpr evaluates a fixed trusted elementwise expression. Its accepting smoke produces the exact weighted squared terms [1, 8, 27, 0], and a deliberately incomplete fixed expression produces a SyntaxError. The later energy comparison gathers the source and target potentials for each edge, evaluates the weighted squared differences, and compares the sum with the frozen scalar. No arbitrary external expression, file named by a payload, private record or code supplied in a source document is executed. Expression support is a capability, not permission to evaluate any string encountered during research.

NumExpr's maximum and active thread counts are set to two before import. The optional numerical work is intentionally small. That choice respects the present laptop's workload without making a claim about the ideal setting for every machine. No model-speed or billing benchmark was conducted. In particular, the successful package checks do not measure Fast-mode consumption, context capacity, prompt-cache retention or another sibling's performance. Reported timing or resource facts must have their own measurements and denominators.

A point-in-time OSV query returned no listed advisories for the four exact versions at the time of review. That is the scope of the security statement. It is not exhaustive security, a promise about future advisories or a reason to install unrelated packages without review. The SymEngine project also documents binary dependencies with their own licences, including Windows-specific components. Wheels remain in the D-drive tool bank; this phase does not redistribute those binaries in its Git artifacts. A later distribution or deployment would need a review appropriate to that action.

The earlier family package catalogue remains context, and the current phase used existing tools when they fit the task. Ruff checked the newly written modules for syntax and undefined-name classes. The official Skill Creator validator checked local skill frontmatter. The current weighted-route reviewer checked the owner profile and prospective schedule. Standard-library exact arithmetic and structured JSON were used for the main calculation and evidence paths. These observations do not imply that every one of the family's many installed packages was exercised in this phase.

The main geometry evaluator has limits of 32 vertices, 64 facets or edges where applicable, simplex dimension at most three, and small exact matrices. Scalar admission rejects booleans and values outside the declared integer range. Exact Python integers may produce JSON numeric tokens larger than a JavaScript reader can represent exactly; a downstream consumer must preserve those tokens or introduce an explicit string-number profile. The frozen examples stay within their documented bounds. A later interoperability claim needs tests of that consumer, rather than an assumption that all JSON readers preserve every integer.

If a package becomes unsuitable, deactivate this environment's entrypoint and retain its wheel and receipt evidence. Do not erase an old installation receipt to make a replacement look original. A new package selection should name the concrete job it performs, its compatibility needs, the exact artifact reviewed and at least one meaningful accepting and adverse use. Three useful additions with clear evidence are preferable to a larger count of packages that were merely downloaded and never used.
