# 07 — Process observations, CFR and separated failure credit

Each core session used one initial nine-hundred-envelope production process: three hundred accepting requests, three hundred invalid-horizon requests and three hundred annotated clones. Both returned all expected envelopes and per-request statuses on their first execution. Exact stdin, stdout, stderr, byte counts, digests, request indices, process status and implementation digests are retained. A successful batch process is not a successful invalid subject. Each invalid candidate and clone stays failed with zero original credit; a correctly matched refusal is a separate passing witness.

For every contract, CFR reads the complete definition, expected envelope, status and boundary, then removes only the annotation from a detached in-memory clone and compares the restored request with the original canonical request digest. This is reversible model-record housekeeping, not filesystem deletion or real host cleanup. It supplies one review/restoration task with two explicit observations and does not create extra core proposal credit. The domain ledgers each contain ten methods and 2,100 witnesses: 600 failed subjects and 1,500 bounded passes.

Local guide smokes and installed-pair smokes use separately defined fresh inputs. The twenty extra tests and five model refusals also have their own frozen definitions. These are auxiliary checks rather than additional core contracts or independent experiments. No source engine, successful core tranche, successful guide smoke or successful official metadata validator was replayed for a clearer receipt. A future correction must retain original outputs and isolate only the changed dependency; it may not relabel a failed subject as successful because a refusal worked.
