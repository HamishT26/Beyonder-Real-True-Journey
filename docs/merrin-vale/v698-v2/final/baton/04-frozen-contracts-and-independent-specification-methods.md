# 04 — Frozen contracts and independent specification methods

The program contains six hundred new operation/input contracts across thirty shared profiles and twenty operation interfaces. It does not claim six hundred independent algorithms, experiments, devices or systems. Each session receives three hundred safe accepting definitions, three hundred invalid-horizon candidate subjects, three hundred annotated detached clones and three hundred complete review/restoration tasks. The complete requests, expected envelopes, statuses, falsifiers, practice links and authority limits were frozen before implementation. JSON object-key order is immaterial to logical equality, while every field and ordered array member must match. Exact input and output bytes retain separate hashes.

The definition oracle enumerates finite set partitions, definable unions, complete paths and feature subsets. Production independently uses normalized cells, union-find, bitsets, frontier propagation and coverage dynamic programming. That algorithmic separation is useful same-owner checking, not independent team reproduction. The production module never imports the definition oracle. Profiles have two through six supported states; core examples use four through six. Horizons range from zero through four, feature counts from one through six, and costs are positive integer model units. Unknown fields, duplicate JSON keys and unsupported shapes or bounds are refused.

Novelty is limited to the declared inspected corpus: three hundred inherited selections, six hundred Neris titles and one hundred earlier Merrin titles. No exact normalized new title collision was found there. This is not universal novelty across all family history or mathematics. Caps are ceilings, never instructions to create unsafe activity or manufacture missing real-world prerequisites. Fifty exact-review packets and thirty blocked portfolios remain unexecuted planning records.
