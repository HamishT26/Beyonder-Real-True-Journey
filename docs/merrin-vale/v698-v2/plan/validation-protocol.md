# Frozen validation and accounting contract

Input contracts and complete expected envelopes are frozen before either production tranche. JSON object-key order is immaterial to logical comparison; every field and ordered array member must match. Exact serialized input, output and error streams retain independent byte hashes and process status. Definition digests use recursive sorted object keys with array order preserved, excluding the digest field itself.

Each production stage has one initial batch of nine hundred envelopes: three hundred safe requests, three hundred invalid-horizon requests and three hundred annotated detached clones. Each envelope carries its request index, per-request status and complete result. A batch process finishing successfully does not turn a refused candidate into a successful subject. For each core definition, retain seven Method Flow witnesses: safe comparison pass, candidate subject fail, candidate refusal pass, clone subject fail, clone refusal pass, complete definition review pass, and detached restoration pass. Candidate and clone subjects always have zero original success credit. The two CFR observations form one complete review/restoration task, not two new proposals.

A stage's guides use newly defined smoke profiles with fresh structural inputs; installed curated callers use separately defined inputs. They are not replays of source or successful core requests. Retain exact stdin/stdout/stderr and process metadata. An execution latch is exclusive. After failure, preserve the original stream and run only the failed or changed dependency under a new explicit recovery contract. Never replay an unchanged successful production tranche for a clearer receipt.

Planning oracle algorithms enumerate all partitions, definable unions, concrete paths and feature subsets. Production algorithms will use independent union-find, bitsets, frontier propagation and coverage dynamic programming. Both remain same-owner checking under one infrastructure, not independent reproduction. The oracle is not imported by the production engine.

Targets and choices are sorted unique sets; choices use labels zero through two. One through six feature partitions have positive integer costs one through nine. Goal pairs are sorted unique unordered pairs. Horizon is zero through four, abstract paths have one through five valid cell labels, and model budget is zero through twenty. All names and enum strings are bounded. Unknown fields and duplicate JSON keys are refused. A single request is capped at sixty-four kilobytes; a batch at four megabytes and two thousand envelopes.

All metadata validation is owner-scoped and uses explicit ledger paths, never a broad filename selector that can confuse an index with a ledger. Official ledger and catalogue validators run once on each new object. Their stored receipts and input hashes are canonical inputs; the canonical does not invoke them again. Catalogue caller links and literal transitive dependency closures are checked against each guide's complete contract in addition to the official structural check.
