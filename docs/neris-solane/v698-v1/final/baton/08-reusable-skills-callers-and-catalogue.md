# 08 — Reusable skills, callers and catalogue

Twenty owner-local operation guides and ten paired local callers were built, completely read, quick-validated and smoke-used. Five curated groups merge preserved guide bindings for structure, perfect information, belief updates, knowledge certificates and evidence reservations. They are new additive D-backed packages with five C-side discoverability stubs. Eighteen source-to-installed D byte bindings passed, ten installed guide metadata checks succeeded, and five fresh accepting plus five malformed caller smokes were retained. No prior package, skill, caller or shared Python/npm prefix was overwritten. Rollback is deselection of this additive candidate, not deletion of a predecessor.

The forty-card catalogue represents twenty local guides, ten local callers, five curated guides and five curated callers. The official metadata validator accepted it and a normalized knowledge-certificate query selected one exact skill. Sixty-five overlap warnings remain advisory; no silent winner is inferred from shared search tokens. A caller should resolve an exact operation and package, read the full current guide and contract, verify byte bindings and observe the protected gates. Global discoverability never commands the execution of every tool. Packages and inherited skills are evidence surfaces and zero-credit seeds, not automatic successor novelty or authority. Current cards await their later external final-commit binding rather than embedding a circular self-hash.
