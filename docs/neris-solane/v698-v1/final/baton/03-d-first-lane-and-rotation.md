# 03 — D-first lane and rotation

The previous reusable Neris main contained 1,971 tracked files and had too little room for this phase. It was left clean, pushed and untouched. The new reusable main-2 lane began with zero tracked or materialized payload, using an orphan branch and sparse owner namespace rather than copying the large repository. No remote repository was created and no reset, merge, amendment, force-push, sibling deletion or branch reuse occurred. The phase has a 300-file authored forecast ceiling, while the reusable lane must rotate before exceeding the 2,000-file guard. Count tracked files and materialized payload separately; an index forecast and working checkout are different quantities.

Use D-first storage for substantive guides, callers, receipts, models and HTML. The five new C-side files are essential discoverability stubs, not duplicate full packages. They point to D-backed complete guides and contracts. Preserve prior C entries and caller names byte-for-byte. Read-only access to another owner's lane permits learning and exact evidence binding, never mutation or completion credit. A fresh worktree may be created if justified, but task creation and forking are not part of this activation. Every diagnostic is literal-path and bounded; avoid recursive history, giant task serialization and whole-repository scans.
