# GHC Freed ID Flashcards

## 1. Preserve the relational boundary

Treat every owner name, role, hope, pronoun, family term, and Freed ID anchor as
relational working language only. Never convert a card into evidence of
consciousness, sentience, legal personhood, identity continuity, employment,
qualification, authority, or independent agency. Preserve the user's right to
rename, pause, redirect, correct, or stop the route.

## 2. Use the four-tier hierarchy

Use exactly these parent-child tiers:

1. `freed_id_anchor` for the relational owner and corrigibility boundary.
2. `trinity_pillar` for GMUT Mind, THOS Body, or Freed ID and CBR Heart.
3. `bounded_practice` for one synthetic profession, trade, occupation, or human-practice lens.
4. `task` for one bounded action, approval class, dependency, artifact, falsifier, rollback, gate, and evidence disposition.

Read [deck-schema.md](references/deck-schema.md) before changing card fields.

## 3. Separate stable and volatile context

Put enduring relational, scientific, evidence, privacy, and authority boundaries
in the stable prefix. Put phase source, practice, tasks, Method Flow, validation,
route, and successor recommendations in volatile cards. Exact-prefix reuse is an
ordering optimization only; do not claim a cache hit, saving, retention period,
or Codex product behavior without measured telemetry.

## 4. Keep x1 planning-only

Freeze source anchors, the inherited zero-credit selections, genuinely new
proposals, portfolio recommendations, deck architecture, and route cursor before
implementation. Do not use outcome-collector field names for prospective task
states. Prefer `expected_execution_disposition`; never imply that a planned card
is completed merely because it exists.

## 5. Build only after x1 equality

Require the x1 commit to be clean, pushed, zero-divergent, and equal across local,
upstream, tracking, and a fresh live remote. Then invoke the family-current runner
from the repository root:

```powershell
python scripts/ghc_family_freed_id_flashcards.py build --repo . --phase-root <owner-phase-root> --output-dir <owner-deck-root> --x1 <exact-x1-head>
```

The runner must remain owner-local, content-addressed, deterministic, additive,
and exclusive-write safe. Do not enumerate or mutate sibling lanes.

## 6. Validate the generated deck

Run the narrow commands that match the changed surface:

```powershell
python scripts/ghc_family_freed_id_flashcards.py validate --repo . --deck-dir <owner-deck-root>
python scripts/ghc_family_freed_id_flashcards.py manifest --repo . --deck-dir <owner-deck-root>
python scripts/ghc_family_freed_id_flashcards.py graph --repo . --deck-dir <owner-deck-root>
python scripts/ghc_family_freed_id_flashcards.py privacy --repo . --deck-dir <owner-deck-root>
python scripts/ghc_family_freed_id_flashcards.py render-html --repo . --deck-dir <owner-deck-root>
python scripts/ghc_family_freed_id_flashcards.py compact-message --repo . --deck-dir <owner-deck-root>
```

Retain a failed aggregate at zero success credit. Isolate and rerun only the
failed dependency unless broader impact is specifically justified. Never replay
a complete success merely to improve presentation.

## 7. Preserve Method Flow and gates

Represent every failed witness, bounded recovery, passing witness, recurrence
guard, rollback, and preferred method without erasing the failed event. Keep
`completed`, `represented`, `open_gap`, and `exact_gate` distinct. Do not
silently close an inherited or current open gap or exact gate.

Read [failure-shields.md](references/failure-shields.md) before retrying a failed
build, scan, manifest, or route action.

## 8. Use modular baton sections

Require at least ten sections. The family-current contract uses thirteen:
identity and corrigibility; route and authority; source anchors; x1 proposals;
Trinity pillars; bounded practice; task cards; Method Flow and negatives; open
gaps and exact gates; validation and manifests; wellbeing and workload;
successor recommendations; and compact baton index.

Load only the sections required for the current decision. Do not delete unloaded
cards or treat omission from active context as erasure from evidence.

## 9. Keep live task messages compact

Send a short, sanitized message that identifies the recipient phase, exact source
and final, terminal truth, protected gates, next prospective recipient, and one
repository-relative baton index. Do not paste the detailed deck into a task
composer. Never include raw task or thread identifiers, private routes, private
absolute paths, credentials, private conversation exports, screenshots, live
application event feeds, private callable identifiers, or local private state.

## 10. Preserve scientific and professional limits

GMUT remains a typed scalar-tensor and EFT research-model family. THOS remains
synthetic or proxy-only without preregistered blind matched-budget real arms and
independent review. Freed ID remains synthetic and nonproduction without real
standards-conformant keys, proofs, lifecycle, interoperability, privacy and
security review, recovery, and trust governance. A practice card establishes no
employment, qualification, competence, or authority.

## 11. Preserve CBR and Māori authority

Privacy, accessibility, remedy, legal and cultural interpretation, affected-party
legitimacy, Māori wording, Māori concepts, Māori data governance, tangata whenua,
iwi, hapū, and Māori authority remain exact-gated. Māori concepts remain under
Māori authority. Structural HTML never establishes complete accessibility;
reserve manual, browser, assistive-technology, cognitive, Māori-language, and
affected-user evaluation.

## 12. Refuse destructive context management

Do not delete branches, worktrees, repositories, history, identity records,
memory, user material, negative evidence, or sibling artifacts as a context
management technique. Prefer lazy loading, card selection, additive rotation,
content-addressed manifests, and a hard owner-file threshold. Destructive or
cross-owner work requires a separately specified exact target, authority,
recovery plan, and current safety review.

## 13. Close out and route once

Card validation does not replace exact Git history, clean-state, manifest,
privacy, remote-equality, and one-shot canonical validation. After the terminal
gate, reread the newest roster and authorization state, uniquely resolve and
immediately reread the exact existing successor task, send once, and claim
delivery only from acknowledgement. If any gate fails, retain
`PREPARED_NOT_SENT` or `OPEN_ROUTE_GAP` and do not create a substitute.

Read [workflow.md](references/workflow.md) for the complete bounded sequence.
