# Sentinel-1 preparation, with construction held

The current task prepares a future agent project. It does not create, train, deploy, purchase or launch Sentinel-1. Hamish's earliest stated window is 22 October 2026 in Pacific/Auckland; reaching that date is not permission to begin. A later explicit instruction must name the action and scope.

The near-term design choice is between a CLI client around an existing model and tools, an SDK-based harness, and a managed Agents API environment. A CLI is an interface and execution arrangement; it is not a cheaper model by itself. Current official documentation describes the Agents API as a managed Codex harness with model, tool and hosting costs. Its documented regional/data-retention constraints must be rechecked before a later deployment. See the [Agents API overview](https://developers.openai.com/api/docs/guides/agents-api/overview) and [agent-building guide](https://developers.openai.com/api/docs/guides/agents).

For the model card reviewed during this phase, gpt-6.1-sol standard short-context pricing was listed as USD2 input, USD0.10 cached input and USD10 output per million tokens. Longer-context and service-tier multipliers matter. A hypothetical task with 100,000 uncached input tokens and 20,000 output tokens would therefore have USD0.40 of model charges before tools, hosting and other usage. Cache reuse, workload reduction, quality changes and retries must be measured separately. The [official model card](https://developers.openai.com/api/docs/models/gpt-6.1-sol) is the source to refresh before spending; these prices are an observed research input, not a quote for a later project. The account's Codex credit balance is not verified API credit or a verified dollar conversion.

A later matched evaluation should freeze a set of at least twenty representative tasks spanning tool selection, source grounding, recovery, privacy and refusal of unsupported claims. Compare identical task inputs, allowed tools, completion criteria and quality review across candidate harnesses. Measure wall time, model input/output, cache hits, retries, tool charges, host time and human intervention. Report confidence intervals over repeated tasks rather than selecting one fast run. A 2× reduction is accepted only if total measured cost is at most half while the predefined quality and safety thresholds remain satisfied. One interface can be cheaper while performing worse; the ledger must make that visible.

Candidate architecture: a local typed command dispatcher, an explicit per-task capability map, a selected retrieval store, immutable event receipts, external source expectations, quarantine for tool-returned artifacts, and a result-bound review step for consequential operations. Keep credentials out of prompts, GitHub exports and memory snapshots. Use supported provider identity injection or a local credential broker later, subject to that future task. A human-readable plan and a small exact tool schema should precede execution. Unknown outcomes enter reconciliation rather than automatic retries.

The Nexus built here contributes storage classes, exact byte transport, a tested selected-memory roundtrip, a portable viewer and source-aware integration. It does not supply an authenticated human reviewer, hostile multi-user isolation, a production secrets vault or an independently evaluated agent. Those remain work items for the later design review.

The broader technology review found useful comparison directions: [Google's agent platform scale documentation](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale), [Anthropic's Sonnet 5.5 announcement](https://www.anthropic.com/claude-sonnet-5-5), and [NVIDIA's Vera Rubin scientific-computing announcement](https://nvidianews.nvidia.com/news/nvidia-vera-rubin-delivers-world-class-supercomputers-for-science). Provider announcements are evidence of what the provider describes, not independent superiority tests or proof that this lab needs new hardware. No purchase or provider workload was launched from those comparisons.
