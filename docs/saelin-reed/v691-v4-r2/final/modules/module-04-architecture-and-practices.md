## Module 04 — Architecture and four practice lenses

The module interface is evaluate({operation,input}), returning {ok,error,value,authority:false}. It has closed input keys, bounded arrays, safe integer quantities and explicit outcome ceilings. The x1 engine implements ten recovery operations. The x2 engine retains that interface and adds ten simulation, exact arithmetic and evidence operations. Five public runners expose coherent four-operation groups. The browser package uses the same model through a separately checked SHA-256 adapter and module bundle.

The models do not call task tools, inspect private history, restart services or charge an account. Native task operations remain explicit terminal actions outside the pure engine. This separation makes it possible to test uncertain outcomes without creating real duplicate activations. It also lets the interactive world present errors, resources and consent as inspectable state.

Site reliability engineering contributes service-surface separation, bounded retry planning and cost accounting. Formal methods engineering contributes finite-state search, exact fractions, temporal paths and counterexamples. Accessible interface design contributes keyboard controls, textual outcomes and withdrawal behavior. Archival curation contributes source hashes, stable references, correction lineage and preservation of prior evidence. These are learning lenses rather than professional qualifications.

The four-tier deck has 208 cards: one owner anchor, three pillars, four practice lenses and two hundred task records. Every non-owner card has exactly one parent in the immediately preceding tier. A practice’s primary pillar is a lens; a task may separately identify cross-pillar work. The index makes that distinction explicit. Missing parents, tier skips, multiple parents, duplicate identifiers and invalid outcomes were refused.

Twenty local guides and ten local runners remain available in their phase directories. Five global merges preserve their source callers. The shared v6 reviewer checks the publication snapshot and all 277 assignments without activating a task. The Meta Tool Box records forty-two current capabilities and preserves recent source catalogues as provenance.
