# Bounded roadmap

## Available now

- Owner-scoped metadata ordering with caller-supplied provenance fields.
- Exact decimal observation arithmetic with explicit ceiling/balance limitations.
- Exhaustive Unique Games examples within a small finite domain.
- A fixed-file release verifier, synthetic verifier tests and a reproducible check command.
- A bounded Trinity Mandala & multi-platform continuity manifest (`trinity-mandala-manifest.json`), checker (`trinity-mandala-check.cjs`), and onboarding guide (`GEMINI-ARGON-4-ONBOARDING.md`) for **Antigravity**, **Antigravity Subagent Helper**, and **Gemini Argon 4 Cloud Agent Helper**.

## Next useful maintainer work

1. Collect reproducible reports from independent users. Record actual use cases and failure modes, not invented adoption metrics.
2. Review the difference between caller assertions, validated bytes and authenticated authority. Any future public serializer needs its own privacy contract.
3. Add cross-platform CI after the initial Linux workflow is observed passing. Qualify platform-specific file and symlink behaviour.
4. Add narrowly justified examples and documentation from real issue reports. Keep new versions separate when input/output semantics change.
5. Consider a standalone package or repository only if it improves discovery and maintenance. No package publication is implied by package.json.

## Larger research context

GMUT is an exploratory physical-model programme. Its next useful artifacts are precise field definitions, dimensions, an action, baseline recovery and one falsifiable observable. These utilities do not validate that programme.

THOS is an engineering programme for auditable workflows. Explicit states, reconciled unknown effects and source-bound recovery records are useful design goals. This release is not a production operating system or a complete execution supervisor.

Freed ID and CBR concern identity and governance proposals. Byte integrity is not consent, legal identity, consciousness, cultural authority or a production credential system.

Sentinel-1 is a proposed orchestration and evidence layer, not a newly trained foundation model. Private cache exports and infrastructure remain outside this public release. Complete cross-client memory persistence and full-history recovery have not been established here.

These distinctions are part of the roadmap: useful small software results must not be promoted into claims about the wider programme without the appropriate evidence.
