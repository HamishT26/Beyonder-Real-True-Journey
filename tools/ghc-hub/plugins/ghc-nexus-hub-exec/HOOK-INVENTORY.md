# Canonical shared Nexus checks

Owner: `ghc-nexus-hub-exec`, version 0.1.1. One `PreToolUse` / `^Bash$` command registration invokes `scripts/nexus_preflight.cjs`. The Admin, Computer Use and Config Menu packages register no hooks. Five logical checks share that one process.

| Check ID | Concrete scope | Existing coverage reviewed / distinct behavior |
|---|---|---|
| `source_manifest` | Before a recognized Hub effect, compare eleven selected installed module hashes with `references/hub-source.json`; aliases remain unverified. | Existing phase source/branch reminders do not compare the selected Hub runtime bytes. |
| `config_schema` | Recognized Config Menu proposals: inspect three permitted display keys and their JSON value types. | Existing model-change reminders do not validate these proposal values. |
| `secret_export` | Flag sensitive-looking literals and memory exports without 1–30 unique explicit safe record IDs. | Existing output/identifier advice does not perform this selected-memory-export check. It is not a complete secret scanner. |
| `selected_route` | Recognized Hub action names, required exact chat selection and explicit execution marker; compound/unclassified shell forms get a limited notice. | Existing no-resend hooks remain separate; this check does not resend, activate or unlock a chat. |
| `budget_admission` | Numeric finite-lab size of 1–200000, including malformed/duplicate size options. | The existing SessionStart budget reminder does not inspect each finite-job size. This check does not attest billing or reserve funds. |

The reviewed cache inventory contains five hook packages: Coordinator, phase guards, laboratory-v20, Talen and Ilyra. Inventory evidence is in the candidate bundle's `evidence/existing-hook-inventory.json`. This is a bounded inventory of those cached packages, not proof that every hook is currently enabled on every host. Compare any additional live registrations at integration.

Input is capped at 32768 bytes. An unfinished input stream gets a one-second in-process timer; the registration has a five-second outer timeout. Timers are not hard scheduling guarantees on a stalled host. Outputs are `{}` or a fixed `systemMessage`; no `continue`, permission grants, command rewriting, raw command echoes, file writes, network calls or subprocesses are used. There is no Stop hook. Runtime checks are advisory, not a substitute for Hub validation, provider locks, protected-target restrictions or current user authorization.

Installation does not grant hook trust. Review the current definition through the host's supported hooks control before enabling it. Never synthesize trusted hashes or copy a trust decision from another package. Runtime event dispatch remains unverified until a deliberately selected harmless event is observed in that host.

For the Meta Tool Box, add one row for this canonical handler with: package/version, manifest hash, five check IDs, event/matcher, platform runtime path, input/time bounds, definition hash, trust state, last observed dispatch and rollback version. Link the four plugin skills to that row instead of registering additional copies. Refresh source pins only from the integrator's reviewed release manifest; a newer source worktree is not an installed release.
