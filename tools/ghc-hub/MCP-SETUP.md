# GHC Nexus MCP client setup

The installed mcp-server.mjs serves nine fixed read-only tools through the official MCP SDK 2.3.1. Public results contain selected aliases, booleans and bounded route/plan enums. There is no shell tool or automatic chat sender. Native chat messaging continues through the authorized native client.

For the reviewed Windows installation, add the local STDIO server with the supported standalone CLI:

    codex mcp add ghc_nexus -- D:/GHC-Archives/global-tools/node/26.11.1/node-v26.11.1-win-x64/node.exe D:/GHC-Archives/global-tools/ghc-nexus-hub/mcp-server.mjs

The parent's supported config and plugin reload determine when its tool catalogue becomes available. Registration is not a completed client call. Keep a private exact config backup and inspect the resulting TOML diff.

For ChatGPT or another authorized remote OpenAI client, use the official Secure MCP Tunnel client with a reviewed tunnel in the intended organization and workspace. The Windows binary and native profiles are stored on D. The tunnel runtime may use a private credential-file reference; never put an actual API key in command arguments, repository files, logs or shared receipts.

Use tunnel-client runtimes connect with an existing tunnel ID, the exact reviewed STDIO command, and a private profile directory. Then inspect runtimes status in JSON. Only a running, healthy and ready runtime establishes that layer. Connector discovery and an actual read-only tool call establish separate client layers. Do not use an ad hoc public tunnel or broad proxy as a substitute.

On Linux, use a separately reviewed installation and supported local paths. A Windows D drive is not an implied Cloud mount. Managed Cloud network policy and credentials remain under that executor's provider. A denied model endpoint is not repaired by granting access to this read-only MCP server.

Codex CLI 0.161.0 adds /mcp login <name> inside an active terminal session. The existing codex mcp login <name> command remains the separate OAuth route for compatible remote MCP servers. Local STDIO servers and App-brokered connectors do not automatically acquire each other's authentication.
