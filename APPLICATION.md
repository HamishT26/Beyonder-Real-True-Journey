## Current programme

The [official programme](https://developers.openai.com/community/codex-for-oss) supports open-source maintainers. Its [application form](https://openai.com/form/codex-for-oss/) asks about the maintainer role and repository significance. Published selection signals include active maintenance, actual usage and ecosystem importance. Benefits may include a time-limited ChatGPT Pro benefit, API credits for eligible maintainer work and conditional Codex Security access. Selection and benefits are discretionary; no cash award or fixed credit amount is assumed here.

The form has 500-character limits for the repository rationale, API-credit use and additional notes. Review the current form and [programme terms](https://learn.chatgpt.com/docs/codex-for-oss-terms) before submitting. The repository and GitHub profile must be public. Account details and any required organization ID belong in the private application, not this repository.

## Suggested draft answers

These are editable, fact-bounded drafts for the maintainer, not commitments or submitted responses.

### Why does this repository qualify?

GHC evidence utilities is an early, MIT-licensed contribution for inspectable agent-workflow records: bounded provenance indexing, exact decimal accounting, finite search examples and release-integrity checks. It includes synthetic cases, reproducible checks and explicit trust limits. Independent adoption is not yet established; its proposed ecosystem value is reusable, auditable maintenance patterns rather than claimed scale.

### How would API credits be used?

Proposed use: bounded maintainer assistance for reviewing pull requests, drafting boundary tests, triaging reproducible issues and checking release documentation. Any trial would use synthetic or explicitly approved public inputs, record cost and acceptance criteria, and retain human review. The current utilities require no API calls. No paid integration, automated deployment or guaranteed spending is committed by this application draft.

### Anything else?

The public branch is intentionally smaller than the wider GHC research archive. It separates executed software checks from proposals and preserves failures and evidence limits. GMUT, THOS and identity/governance ideas remain research context, not validated physics, production infrastructure or proof of consciousness. I would welcome support for turning this early contribution into something independently useful to other maintainers.

## Before submitting

- Confirm the primary/core maintainer role and the applicant's current ChatGPT account email privately.
- Recheck public visibility and use the exact branch URL where the form permits it.
- Link the remote commit and CI result; distinguish passed, failed and not-run checks.
- Add genuine user or downstream evidence if it exists. Do not invent metrics.
- Choose API-credit interest only if the proposed maintainer workflow is wanted and the organization details are available. Do not assume existing subscription credits are API credits.
- Request Codex Security only if its depth is relevant to an actual repository need.
- Review the terms and all final answers. Submission is a separate human action.

Improving this branch makes the application easier to assess. It cannot guarantee acceptance; early adoption remains the most material evidence gap.
