# CD30R seven-phase coordination cadence

Updated: 23 November 2026 (Pacific/Auckland). Programme: CD30R-20261123. Governing bundle policy: B01 Revision03.

## Current instruction

Use seven consecutive phases per consolidated owner message, with both x1 and x2 in each phase. This supersedes the earlier three- and ten-phase spans. Continue from each owner's actual checkpoint and preserve completed work; a cadence revision must not cause a replay or erase a failure.

## Work and evidence

Per-phase portfolios and per-substage targets remain in force. At least thirty substantive tasks per x1 and thirty per x2 yields a target of 420 task units per owner across a full seven-phase bundle. This is a planning target, not an achieved count. A carried project needs a distinct new deliverable before receiving new credit. Do not fill targets with repeated plans, trivial tests or duplicate sources.

A ready owner may continue prepared, authorized independent work without a new message just to open the next substage. Freeze exact source and case identities, complete expectations, runtime selection, resource/time/output bounds and cleanup before a new run. Inspect peer source before importing it. Record producer evidence, independent document review and independent reproduction separately.

A blocked project retains its exact prerequisite. Continue other useful independent work and carry unfinished scope explicitly. Whole-programme phase closure requires a reconciliation of actual accepted deliverables, counts and deficits; an assignment or producer pass alone does not establish closure.

## Mid-run coordination

Use the existing shared Hub and liaison mailbox at each x1/x2 boundary, when a peer artifact is needed and when a material issue appears. Read current coordination before consuming peer artifacts. Include programme/bundle/phase/substage, owner, actual work, evidence class, artifact identity, prior failures, in-flight state and next dependency.

Send one consolidated kickoff to each existing original conversation. Delivery, acknowledgment and completion are distinct states. A mailbox post is not an automatic wake-up mechanism. Reconcile drafts and prior sends before retrying. Preserve an active response; use a targeted follow-up only for a concrete correction or dependency. No new agent, replacement chat or timer is created by this cadence policy.

The existing Gemini conversations remain available for useful local support under the established phase rotation. Their automatic mode does not satisfy a human-only approval requirement. Local implementation and execution still require the applicable exact scope and platform conditions.

## First-bundle progression

Phases01–03 continue the current owner-specific implementation, source review, interfaces and research. Phase04 addresses concrete contract gaps. Phase05 investigates meaningful failures and counterexamples. Phase06 integrates reviewed interfaces and reconciles end-to-end evidence. Phase07 develops accessible presentations and assembles the actual portfolio, carried deficits and prepared08–14 handoff. Every phase retains both x1 and x2.

## Preserved boundaries

Historical CD30 is separate from the new CD30R programme. Historical UNRUN cases, same-ID corrections, prior failures/counts, unknown effects, consumed approvals, held banks, owner holds, Windows receipt qualifications and publication review remain intact. No old operation is replayed or released merely because the cadence changed.

Scientific and mathematical claims retain their evidence class. Numerical agreement does not validate GMUT; a source assessment is not full-paper reproduction; a proposed refinement is not an accepted result. Keep separate overview and research-paper targets, source publication dates, exact word counts and unresolved contradictions visible.

Consolidation reduces avoidable owner-message dispatches. It does not prove a fixed account-level quota saving or remove context/runtime limits.
